## Phase 1 — Release blockers (High)

### [x] 1.1 Route names are invisible under a cached route table → every admin Inertia page 500s (REL-2)

- **Where:** `src/Http/ArtisanPackUIRoutes.php:128-188` (every route uses a
  trailing `->name()`), `src/ArtisanPackUIServiceProvider.php:208-210` (asset
  route), `:260-267` (`refreshNameLookups()`), `src/Support/PluginBootstrapper.php:64-120`
  (`Inertia::share` closure calls `route('artisanpack-ui.*')`).
- **Problem:** Keystone's installer runs `route:cache`, and activating or
  updating a plugin doesn't clear it. Under a cached table the router uses a
  `CompiledRouteCollection`, whose `refreshNameLookups()` does nothing, so names
  attached *after* the verb are never indexed. `route('artisanpack-ui.icons.index')`
  then throws inside the shared Inertia prop, and every admin page returns 500,
  including the Plugins screen. Realistic trigger: updating a live 0.1.1 site to
  1.0 through the updater. (Confirmed in Testbench: names set before the verb
  do resolve.)
- **Fix:**
  1. Put every route name *before* the verb, e.g.
     `Route::name('settings.update')->put('settings', [SettingsController::class, 'update']);`
     Keep group `->name()` prefixes, `->where()` and `->middleware()` as they are
     (`->where()` may be chained after the verb).
  2. Do the same for the asset route:
     `Route::name('plugins.'.self::SLUG.'.assets')->get(...)->where('path', '.*')`.
  3. Defence in depth: in `PluginBootstrapper::boot()` wrap endpoint building in
     `try { … } catch (\Symfony\Component\Routing\Exception\RouteNotFoundException $e) { Log::warning(...); return []; }`
     so a missing name can never take down the shared prop.
  4. Same file: return `[]` from the share closure unless
     `$request->is('admin/*')` **and** `Gate::allows(Permissions::ACCESS)`.
     Today the endpoint map is shared on every Inertia response, guests
     included (SEC-10.2).
- **Test:** new `tests/Feature/RouteCacheTest.php`: compile the current routes
  into the router (`app('router')->setCompiledRoutes(app('router')->getRoutes()->compile())`),
  call `ArtisanPackUIRoutes::register(['web'])`, and assert `Route::has()` for
  every route name `PluginBootstrapper` uses (all JSON routes plus
  `icons.index`). Confirm the test **fails** before step 1 and passes after.

### [x] 1.2 Issue modal forms also submit the Edit Package form (FE-1)

- **Where:** `resources/js/components/board/IssueModal.tsx:165-166` (`save`),
  `:202-203` (`addComment`), `:271`, `:425`, `:444` (`<form method="dialog">`).
  Host: `Modules/ContentModel/resources/js/pages/admin/content-model/DynamicContentEdit.tsx:424-608`
  wraps the `tabs` slot in `<form id="dynamic-content-form">`.
- **Problem:** the Issues tab renders inside the host's form, so the modal's
  three forms are nested in it. React's synthetic `submit` bubbles. `save` and
  `addComment` call `preventDefault()` but not `stopPropagation()`, so the host's
  `handleSubmit` also runs and PUTs the whole package record, saving any
  half-finished field edits. The Inertia visit then closes the modal. A
  backdrop click saves the package and the modal stays open.
- **Fix:**
  ```tsx
  import { createPortal } from 'react-dom';

  async function save(event: FormEvent) { event.preventDefault(); event.stopPropagation(); /* … */ }
  async function addComment(event: FormEvent) { event.preventDefault(); event.stopPropagation(); /* … */ }

  return createPortal(
      <dialog …>
          …
          <form method="dialog" className="modal-backdrop" onSubmit={(event) => event.stopPropagation()}>
              <button type="submit">Close</button>
          </form>
      </dialog>,
      document.body,
  );
  ```
  The portal fixes the invalid DOM nesting. `stopPropagation` is still required,
  because React bubbles through portals. Check that `react-dom` is a shared
  federation singleton (it is) so `createPortal` uses the host's copy.
- **Verify (manual):** Edit Package → Issues → open an issue. Add a comment,
  save an edit, press Enter in the title input, then click the backdrop. The
  Network tab shows only the plugin's requests and no `PUT /admin/content/package/{id}`,
  and the backdrop click closes the modal.

### [x] 1.3 Stale CSRF token after login → every plugin write returns 419 (FE-2)

- **Where:** `resources/js/lib/http.ts:17-37`.
- **Problem:** `csrfToken()` reads `<meta name="csrf-token">`, which is rendered
  once per full page load. Login is an Inertia visit that regenerates the
  session token, so the meta tag goes stale. Laravel prefers `X-CSRF-TOKEN` over
  `X-XSRF-TOKEN`, so every plugin POST/PUT/PATCH returns 419 until a hard
  reload: Sync, imports, reorder, board moves, issue edits, comments and
  Settings save. The host's own APIs read the `XSRF-TOKEN` cookie, which is
  why they keep working.
- **Fix:**
  ```ts
  function xsrfCookie(): string | null {
      if (typeof document === 'undefined') {
          return null;
      }
      const match = document.cookie.match(/(?:^|;\s*)XSRF-TOKEN=([^;]+)/);
      return match ? decodeURIComponent(match[1]) : null;
  }

  // in apiFetch, replacing the csrfToken() block:
  const xsrf = xsrfCookie();
  if (xsrf) {
      headers.set('X-XSRF-TOKEN', xsrf);
  } else {
      const token = csrfToken();
      if (token) {
          headers.set('X-CSRF-TOKEN', token);
      }
  }
  ```
- **Verify (manual):** log out, log in through the form without reloading,
  open Edit Package and click "Sync now". It returns 200, not 419.

## Phase 2 — Security (Medium/Low)

### [x] 2.1 A `sync` user can steal the docs-site API token by changing the URL (SEC-1)

- **Where:** `src/Http/Controllers/SettingsController.php:38-60`,
  `src/Http/Requests/UpdateSettingsRequest.php`, `src/Services/Docs/DocsSiteClient.php:212-224`.
- **Problem:** `PUT settings` sits under `permission:artisanpack-ui.sync`. A
  blank token means "keep the stored one", so a sync user can point
  `docs_base_url` at their own host, then click Test connection (or wait for the
  03:00 job). That sends `Authorization: Bearer <token>` to them. The token has
  write scopes on docs.artisanpackui.dev.
- **Fix:**
  - In `UpdateSettingsRequest`, add an `after()` hook. When a token is stored,
    the submitted token is blank, `remove_docs_api_token` is false, and the
    origin (scheme, host, port) of the new `docs_base_url` differs from the
    stored one, add an error on `docs_api_token`: "Re-enter the API token when
    you change the docs site URL."
    ```php
    public function after(): array
    {
        return [function (Validator $validator): void {
            $settings = IntegrationSettings::current();
            $newToken = trim((string) $this->input('docs_api_token', ''));

            if (! filled($settings->docs_api_token) || '' !== $newToken || $this->boolean('remove_docs_api_token')) {
                return;
            }

            if (self::origin($this->input('docs_base_url')) !== self::origin($settings->docsBaseUrl())) {
                $validator->errors()->add('docs_api_token', __('Re-enter the API token when you change the docs site URL.'));
            }
        }];
    }

    private static function origin(mixed $url): ?string
    {
        if (! is_string($url) || '' === trim($url)) {
            return null;
        }

        $parts  = parse_url(trim($url));
        $scheme = strtolower($parts['scheme'] ?? '');
        $port   = $parts['port'] ?? ('https' === $scheme ? 443 : 80);

        return $scheme . '://' . strtolower($parts['host'] ?? '') . ':' . $port;
    }
    ```
  - Apply the same rule to the GitHub App credentials: changing
    `github_app_id` or `github_installation_id` while a private key is stored
    requires re-entering the key.
- **Tests** (`tests/Feature/SettingsTest.php`):
  - A different host with a blank token returns 422 on `docs_api_token`, and
    the stored URL and token are unchanged.
  - A different host with a new token returns 200.
  - The same URL, or the same URL with a trailing slash, with a blank token
    returns 200 and keeps the token.
  - Changing the App ID with a blank key returns 422.

### [x] 2.2 Issue endpoints reach every repo in the org, and pull requests too (SEC-2)

- **Where:** `src/Http/ArtisanPackUIRoutes.php:172-177`, `src/Http/Controllers/IssueController.php:29-57`,
  `src/Services/GitHub/GitHubIssues.php:55-124, 217-228`.
- **Problem:** `{repo}` only has to match a regex, then gets the org prefixed.
  `/repos/{o}/{r}/issues/{n}` also accepts PR numbers. Through the App's bot
  identity, an `issues.manage` user can read private issues in any repo the App
  covers, and retitle, close, relabel or comment on any issue **or PR**. The UI
  only ever shows the configured project's issues.
- **Fix:** do **3.3** (BE-3) and **4.1** (board cache) first.
  - Inject `ProjectBoardReader` into `GitHubIssues`.
  - Add `assertOnProject(string $repo, int $number): void`, called at the top of
    `show()`, `update()` and `comment()`:
    ```php
    private const PROJECT_ISSUE_QUERY = <<<'GRAPHQL'
        query ($owner: String!, $name: String!, $number: Int!) {
          repository(owner: $owner, name: $name) {
            issue(number: $number) { projectItems(first: 50, includeArchived: true) { nodes { project { id } } } }
          }
        }
        GRAPHQL;

    public function assertOnProject(string $repo, int $number): void
    {
        $this->repoPath($repo);
        $projectId = $this->reader->statusField()->projectId;
        $cacheKey  = 'artisanpack-ui:issue-on-project:' . sha1($this->settings->githubOrganization() . "|{$repo}|{$number}|{$projectId}");

        if (Cache::has($cacheKey)) {
            return;
        }

        $data  = $this->github->graphql(self::PROJECT_ISSUE_QUERY, [
            'owner'  => $this->settings->githubOrganization(),
            'name'   => $repo,
            'number' => $number,
        ])->data;
        $nodes = $data['repository']['issue']['projectItems']['nodes'] ?? null; // issue is null for PR numbers

        foreach (is_array($nodes) ? $nodes : [] as $node) {
            if (($node['project']['id'] ?? null) === $projectId) {
                Cache::put($cacheKey, true, 300);

                return;
            }
        }

        throw new GitHubException(__('That issue isn\'t on the org project.'), 404);
    }
    ```
    The cache only stores positive results.
  - For `options($repo)`: have `ProjectBoardReader::read()` record the
    lowercased `nameWithOwner` set in the cache (same TTL as the status field).
    Add `ProjectBoardReader::repositories(): list<string>`, which reads the
    cache and falls back to `read()`. `options()` throws a 404
    `GitHubException` when `strtolower("{$org}/{$repo}")` isn't in the set.
- **Tests** (`tests/Feature/IssueTest.php`; extend the fakes with an
  `api.github.com/graphql` response):
  - `PATCH` where GraphQL returns `issue: null` (a PR number) → 404, and
    `Http::assertNotSent` for any PATCH.
  - An issue whose `projectItems` names another project → 404, with no PATCH or
    POST sent. Same for `GET` show and `POST` comments.
  - `GET issues/private-repo/options` for a repo not on the board → 404.
  - Update the existing happy-path tests to include the membership fake.

### [x] 2.3 Harden `OutboundUrlPolicy` (IPv6, unresolvable hosts, CGNAT, DNS rebinding) (SEC-3)

- **Where:** `src/Support/OutboundUrlPolicy.php:53-62`, `src/Services/Docs/DocsSiteClient.php:212-224`.
- **Problem:** `gethostbynamel()` returns IPv4 only, so AAAA-only internal
  hosts pass. Unresolvable hosts are allowed. `100.64.0.0/10`, `64:ff9b::/96`
  and `::ffff:0:0/96` pass the filter. The check runs only at save time, so DNS
  rebinding works. A 422 body from the target is echoed back
  (`DocsSiteException::fromResponse`), which lets a user partly read internal
  responses.
- **Fix:**
  - Add `OutboundUrlPolicy::resolve(string $url, bool $allowPrivate): array{problem: ?string, ips: list<string>}`.
    It should:
    - use `dns_get_record($host, DNS_A | DNS_AAAA)`, plus a literal IP if the
      host is one;
    - **fail closed** when nothing resolves;
    - reject each IP with the existing `FILTER_FLAG_NO_PRIV_RANGE | FILTER_FLAG_NO_RES_RANGE`
      checks plus explicit CIDR checks for `100.64.0.0/10`, `64:ff9b::/96` and
      `::ffff:0:0/96`.
  - Make the existing `problem()` a wrapper around `resolve()`.
  - In `DocsSiteClient::request()`, re-run `resolve($url, app()->isLocal())`,
    throw `DocsSiteException` on a problem, and pin the connection to the
    vetted address:
    `->withOptions(['curl' => [CURLOPT_RESOLVE => ["{$host}:{$port}:{$ips[0]}"]]])`
    (wrap IPv6 in brackets).
  - Keep the existing `app()->isLocal()` escape hatch so local dev against a
    `.test` docs site still works.
- **Tests:**
  - `SettingsTest`: extend the "refuses a docs site URL the server must not
    call" dataset with `https://[64:ff9b::7f00:1]/`, `https://100.64.0.1/` and
    `https://nonexistent.invalid/`.
  - `tests/Unit/DocsSiteClientTest.php`: insert a settings row directly
    (bypassing validation) with `docs_base_url = https://127.0.0.1`. Assert
    `packages()` throws `DocsSiteException` and `Http::assertNothingSent()`.

### [x] 2.4 Remote images and same-tab links in issue markdown (SEC-7, FE-8)

### [x] 2.5 Encrypt the cached installation token; flush GitHub caches when settings change (SEC-9, BE-6)

- **Where:** `src/Services/GitHub/GitHubAppClient.php:131-162`, `src/Http/Controllers/SettingsController.php:38-60`.
- **Problem:** the org-wide installation token, valid for up to an hour, sits
  in plaintext in the default cache store (the DB `cache` table here). Saving
  settings never clears it or the cached Status field, so a rotated key or a
  changed org or project keeps working off stale state until the TTL expires.
- **Fix:**
  - Store `Crypt::encryptString($token)`. On read, `Crypt::decryptString()`;
    treat a `DecryptException` as a miss (forget the key and mint a new token).
  - In `SettingsController::update()`, compare the old and new values after
    `fill()`:
    - If the App ID, installation ID or private key changed (or the key was
      removed), call `app(GitHubAppClient::class)->forgetInstallationToken()`
      **before** the save changes the cache key. Capture the old pair first if
      the key is derived from it.
    - If the org or project number changed, call `ProjectBoardReader::forgetStatusField()`.
- **Tests:**
  - `tests/Unit/GitHubAppClientTest.php`: after `installationToken()`,
    `Cache::get($key)` isn't the raw `ghs_…` token, and a second call reuses it
    with no extra HTTP exchange.
  - `SettingsTest`: saving a new private key clears the cached token key, and
    changing the project number clears the status-field key.

## Phase 3 — Backend correctness

### [x] 3.1 Sync and stats runs can overlap → duplicate drafts, unique-key crashes (BE-1)

- **Where:** `src/Jobs/SyncPackages.php:44-47`, `src/Jobs/CollectPackageStats.php:52-55`,
  `src/Services/Sync/DocsPackageImporter.php:40-48,142-150`,
  `src/Models/PackageSyncState.php:30-33`, `src/Models/PackageStatSnapshot.php:51-58`.
- **Problem:** `->withoutOverlapping()` on `$schedule->job()` only covers the
  *dispatch*. The jobs aren't unique, and "Sync from docs" / "Sync now" run the
  same code in HTTP. Two concurrent imports each `create()` the same new docs
  package. `firstOrNew()->save()` and find-then-insert hit their unique indexes
  and throw a `QueryException`, which aborts `runAll()`. `$timeout = 900`
  exceeds the host queue's `retry_after = 90`, so a long run gets re-reserved
  and marked failed.
- **Fix:**
  1. Both jobs: `implements ShouldQueue, ShouldBeUnique`, with
     `public int $uniqueFor = 3600;` and

## Appendix A — Areas reviewed and found sound

- **Authorization:** every route is behind `web, auth, verified, two-factor, two-factor.enroll`
  plus a `permission:` gate. Tab endpoints enforce permissions server side.
  Dashboard widgets are capability-filtered by the host before `getData()`.
- **CSRF and verbs:** no state-changing GETs.
- **GraphQL:** all queries use variables, so there's no injection. REST paths
  are `rawurlencode`d and repo names regex-checked.
- **Secrets:** encrypted at rest and `$hidden`. Settings shows only `has*`
  booleans. A blank submit keeps the stored secret, and removal is explicit.
  The private key is validated with openssl. Nothing secret reaches logs or
  exceptions.
- **SVG:** DOCTYPE and entities are refused, output goes through `SvgSanitizer`,
  writes are atomic and outside the public directory, and icons render as CSS
  masks, never inline HTML.
- **Blade blocks:** all output is escaped, and `chromeStyle` is allowlisted.
- **Asset route:** `realpath` containment, immutable hashed chunks, and
  `remoteEntry.js` served `no-cache` with an ETag.
- **Sync:** per-step isolation, `version_compare` stable-version selection,
  manual icons protected, no title or body overwrites on import.
- **Stats:** unique `(package_id, date)`, nulls preserved, zero-baseline
  guards, no N+1 queries.
- **GitHub auth:** JWT `iat` backdating, token TTL handling, and a single retry
  on 401.
- **Frontend:** hooks rules respected, and `types.ts` matches the PHP payloads
  field by field. Federation exposes and shared singletons are correct, and
  there's no second React. The modal is a native `<dialog>`. TrendChart has a
  text alternative and a data table.
- **Release ZIP:** a single `artisanpack-ui/` root, the right includes and
  excludes, a valid sha256 sidecar, SHA-pinned actions, and a tag/version
  check.
- **PHP 8.2 syntax:** all of `src/` parses under 8.2 (the constraint is being
  raised anyway, in 5.1).
